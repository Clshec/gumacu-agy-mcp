# ChatGPT Integration Options & Architectural Matrix

This document provides a technical evaluation and reference architecture for integrating ChatGPT capabilities into **Gumacu AGY MCP** as of **October 2026**.

---

## 1. Executive Summary & The "Personal Chats" Gap

A common user request is to have Gumacu MCP or Telegram interact directly with a user's **personal ChatGPT account**, specifically reading past personal chats, continuing preexisting web threads, or using the consumer ChatGPT web UI directly through automated tools.

### Key Finding:
> [!IMPORTANT]
> **There is NO official OpenAI external API for reading, listing, or resuming arbitrary personal ChatGPT web chat history.**
> Any attempt to extract personal chat conversations programmatically via browser automation (Playwright/Puppeteer), session token/cookie harvesting, or unofficial internal web endpoints directly violates the [OpenAI Terms of Use](https://openai.com/policies/terms-of-use) (which strictly forbids automated or programmatic extraction of data or outputs) and introduces severe credential leakage and session fragility risks. Such techniques are not supported and are strictly excluded from Gumacu production releases.

## 3. Option B Implementation: Official Workspace Agents Provider

Gumacu AGY MCP implements **Option B** as an isolated, opt-in service provider (`chatgpt-workspace`) accessible via the existing dynamic capability tools (`agy_capabilities` and `agy_dispatch`) and the Telegram bot (`/chatgpt`).

### Architecture & Security Guarantees:
1. **Isolated Provider (Not a Fake Device)**:
   - Does not impersonate a Netcup Linux or Windows host.
   - Cataloged under `"providers"` with `"kind": "provider"`.
   - Disabled by default; does not advertise as online unless valid credentials and approved agents are configured.
2. **Strict Host Allowlist**:
   - Outbound requests strictly target `https://api.chatgpt.com`.
   - Arbitrary base URLs are rejected at configuration time to prevent SSRF.
3. **Approved Agent Allowlist**:
   - Only agent IDs explicitly mapped in environment configuration (`CHATGPT_WORKSPACE_AGENTS`) can be triggered.
   - Arbitrary or unapproved `agtch_*` IDs submitted by clients are rejected.
4. **Credential Safety**:
   - Tokens are read from `CHATGPT_WORKSPACE_PAT` or `CHATGPT_WORKSPACE_TOKEN`.
   - Tokens are never logged, echoed in error messages, or printed in `repr()`.
5. **No Response Content Leak / Honest Status**:
   - The provider explicitly sets `"output_available": False` and `"output_retrieval": "unavailable"`.
   - Directs users to the official `conversation_url` generated by OpenAI for reviewing agent outputs.

## 4. Configuration Reference

To enable the Workspace Agents provider on an installation:

```bash
# Workspace Agent Personal Access Token (PAT)
export CHATGPT_WORKSPACE_PAT="pat_..."

# Mapping of human-friendly aliases to approved OpenAI Workspace Agent IDs
export CHATGPT_WORKSPACE_AGENTS='{"default": "agtch_019a2b3c4d5e6f", "analyst": "agtch_9876543210fedc"}'

# Alternatively, configure a single default agent:
# export CHATGPT_WORKSPACE_AGENT_ID="agtch_019a2b3c4d5e6f"
```

### Dispatching via MCP (`agy_dispatch`):
```json
// Trigger an approved workspace agent:
{
  "device_id": "chatgpt-workspace",
  "action": "trigger",
  "arguments": {
    "agent": "default",
    "input": "Summarize Q3 financial reports"
  }
}

// Query run status:
{
  "device_id": "chatgpt-workspace",
  "action": "status",
  "arguments": {
    "agent": "default",
    "run_id": "apirun_019a2b3c4d5e6f"
  }
}
```

### Telegram Bot Commands:
- `/chatgpt status`: Show provider configuration state and security notices.
- `/chatgpt agents`: List configured approved agent aliases.
- `/chatgpt trigger <alias> <prompt>`: Trigger an agent run and receive the `conversation_url`.
- `/chatgpt run <run_id> [alias]`: Check execution status of a previous run.
